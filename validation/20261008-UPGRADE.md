## 为什么仍需恢复 DTB

新版原装 `/flash/device_trees/g12a_s905x2_2g.dtb` 实际读出：

```text
/vpu/clk_level: 7
/reserved-memory/linux,meson-fb/reg: <0 0x3d800000 0 0x800000>
/sd2@ffe05000: 有 SDR12、SDR25、SDR50；没有 sd-uhs-sdr104
```

因此原装板级 DTB 仍未包含本盒子所需的三项参数；本次更新覆盖自定义 DTB 后发生花屏、恢复后正常，与这些参数一致。现有最终 DTB 已在此次升级中获得用户实机验证。

## Kodi 真实增量与 seek 改善

实机及旧日志确认 Kodi 从：

```text
e0a50435a1434d9b3703954ec766d9aeb9d8fcca
→ 133818b9b80a1e9d57d3fc72520e409f91cf3543
```

两个提交的 Git 历史已发生重排。GitHub compare 显示 diverged、ahead 415 / behind 411，其提交列表与基于共同祖先的文件差异包含大量两版原本都有的 Amlogic 补丁，不能直接作为一天内新增修复清单。

使用以下命令直接比较两个端点树：

```sh
git diff --stat e0a50435a1434d9b3703954ec766d9aeb9d8fcca 133818b9b80a1e9d57d3fc72520e409f91cf3543
git diff e0a50435a1434d9b3703954ec766d9aeb9d8fcca 133818b9b80a1e9d57d3fc72520e409f91cf3543 -- \
  xbmc/cores/VideoPlayer/DVDCodecs/Video/AMLCodec.cpp \
  xbmc/cores/VideoPlayer/VideoPlayer.cpp \
  xbmc/cores/VideoPlayer/VideoPlayerVideo.cpp
```

实际增量为 13 个文件、105 行新增、15 行删除，主要包括：

- 增加 Dolby Vision VS-Engine 将 DV/HDR 转为 SDR 的设置与处理分支。当前 S905X2 日志显示设备不支持 DV，该设置为 false，因此没有证据表明这条分支改善了本次 seek。
- 两处逐包/逐帧调试日志改为 `LOGVIDEO` 组件日志。当前与旧验证日志均为 info 级别，不能把本次改善直接归因于减少调试日志。
- GUI 列表 Reset 时保留仍被引用项的布局/动画状态，在容器销毁时释放；另有 Android 图标尺寸检查，与此 Linux 播放路径没有直接对应关系。

没有发现直接修改 `CAMLCodec::Reset()`、`CAMLCodec::DequeueBuffer()` 或 HEVC seek 恢复流程的增量。因此结论为：**20261008 在该盒子上已获得用户“seek 不再花屏卡顿”的正向实测，但目前未定位到唯一对应的修复函数或提交。** 不将两版原本都有的补丁、未启用的 DV 功能或未变化的固件误标成此次根因。
